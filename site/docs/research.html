CUDA Compatibility research and evidence

CUDA Compatibility helps users test selected CUDA 13 PyTorch paths on older NVIDIA GPUs while keeping hardware identity truthful.

This page reports implementation and test evidence with its limits. It does not claim a CUDA 13 conformance certification, general PyTorch support, or real-world search visibility.

Reproduced on reference hardware

  • A native CUDA 12.4 vector-add baseline passed on three GM200 Maxwell cards at compute capability 5.2.
  • LLVM/Clang 23.1.4 emitted PTX 8.4 targeting sm_52; the Driver API bridge loaded and launched the tested kernels.
  • The process-local facade returned Runtime version 13000 while driver/device queries continued to report the installed NVIDIA stack.
  • The official PyTorch 2.14 CUDA 13 wheel imported, initialized CUDA, enumerated the real devices, allocated tensors, and copied data to the GPU. Stock mm failed in cuBLAS with CUBLAS_STATUS_ARCH_MISMATCH, and stock ReLU reported a missing kernel image.
  • Selected native operators and a synthetic MLP passed the original three-card suite. New float16, strided matrix, cross-stream lifetime, and small SGD/autograd evidence passed on GPUs 1 and 2; GPU 0 remains untested in this increment because it is below the test free-memory floor.

Method and provenance

Correctness checks compare adapter outputs with CPU PyTorch references and exercise selected edge cases, stream ordering, bounds, and explicit unsupported errors. Test cases and commands are maintained in the source repository. A successful run proves only its named operation, arguments, GPU, driver, and software combination.

Limits and open questions

  • No general CUDA 13 runtime/API replacement or binary translator.
  • Only one small first-order float32 linear→ReLU→sum workload with seven non-foreach SGD steps is verified on GPUs 1 and 2; arbitrary autograd graphs and optimizers remain unverified.
  • CUDA Runtime, cuBLAS/cuBLASLt, NVRTC, cuDNN, NCCL, PyTorch CUDA, the Driver API, and R580 library paths were observed in a bounded process-map probe; broad symbol/API compatibility is not established.
  • The seven-step diagnostic measured 2.360 ms median end-to-end latency on GPU 2 and 7.296 ms on GPU 1, with 67,180,032 bytes peak allocated on each; this tiny workload does not predict application performance.
  • Candidate GPU models remain unverified unless specifically identified as reference hardware.
  • The public GitHub Pages endpoint is not yet serving the site, so crawl, index, social-preview, and AI retrieval outcomes remain unobserved.
