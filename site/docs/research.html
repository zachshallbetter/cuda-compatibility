Research papers

Each record below has its own page with its method, results and limits. Every one is project-maintained, not peer reviewed.

  • Running PyTorch's CUDA 13 wheel on a 2015 Maxwell GPU
    How a 2015 GTX TITAN X runs part of PyTorch's CUDA 13 wheel: kernels built for the real chip, a capped CPU fallback, what was shown, and where it stops.
  • Research program: CUDA-era semantics on legacy GPUs
    The charter for this research: one question, six falsifiable hypotheses, the evidence gathered so far, and the method each new result must follow to count.
  • Maxwell native baseline: CUDA 12.4 on three GM200 cards
    A native CUDA 12.4 sm_52 vector-add on three GTX TITAN X (GM200) cards: the hardware, driver, exact commands, and the pass result later work builds on.
  • LLVM NVPTX on Maxwell: sm_52 kernels from LLVM 23
    LLVM 23.1.4 compiled a CUDA kernel to PTX 8.4 for sm_52, and CUDA 12.4 ptxas and the R580 driver ran it correctly on all three GM200 cards in six of six runs.
  • Runtime version facade: CUDA 13 answers on a CUDA 12.4 stack
    One interposed call lets a process see CUDA runtime 13.0 while the driver, device name and compute capability 5.2 stay real. What that proves, and what not.
  • PyTorch 2.14 CUDA 13 wheel on Maxwell GPUs
    PyTorch's official CUDA 13 wheel imports and allocates on GM200 but ships no sm_52 kernels. Which operations now run natively, which fall back, and why.
  • Implementation gap audit: prototype versus platform goal
    A source-level review of the prototype against the platform goal: what each component does today, its evidence, where it stops, and the next step to take.
  • AI answer attribution pilot: baseline results
    108 signed-out answers from Perplexity, Google and Bing on 3 November 2026: none named the author, several credited NVIDIA, and the site missed page one.
  • CUDA 12.9 to 13.0: what changed for older GPUs
    The CUDA 12.9 to 13.0 toolkit changes that matter for older GPUs, taken from NVIDIA's release notes, with component versions and what still needs checking.

Method and provenance

Correctness checks compare adapter outputs with CPU PyTorch references and exercise selected edge cases, stream ordering, bounds, and explicit unsupported errors. Test cases and commands are maintained in the source repository. A successful run proves only its named operation, arguments, GPU, driver, and software combination.

C

Limits and open questions

Not established
  • No general CUDA 13 runtime or API replacement or binary translator.
  • Training is verified only for small MLPs (SGD, momentum SGD, Adam, AdamW) and a Conv2d/BatchNorm2d CNN on GPUs 1 and 2; Transformer and LayerNorm training, AMP, higher-order gradients and arbitrary autograd graphs remain unverified.
  • CUDA Runtime, cuBLAS/cuBLASLt, NVRTC, cuDNN, NCCL, PyTorch CUDA, the Driver API, and R580 library paths were observed in a bounded process-map probe; broad symbol and API compatibility is not established.
  • The seven-step diagnostic measured 2.360 ms median end-to-end latency on GPU 2 and 7.296 ms on GPU 1, with 67,180,032 bytes peak allocated on each; this tiny workload does not predict application performance.
  • Candidate GPU models remain unverified unless specifically identified as reference hardware.
  • The routes and assets on cudacompat.com returned HTTP 200 in a 2026-11-03 audit; indexing of the other pages, search visibility, social-card rendering, and AI retrieval remain unobserved.
D

Negative results, kept

A hypothesis that was held and disproven stays on the sheet. Each entry names the attempt, what happened, and the condition that would reopen it. These are the records most likely to be re-proposed later.

N1Clang for sm_52 without explicit host libstdc++ include paths. Compilation failed: <climits> not found inside the CUDA runtime wrapper. Reopens when: A reference host has a different C++ library layout, or the pinned LLVM build finds its headers itself.KeptCLC-004-llvm-host-cxx-headers
N2Extract the LLVM release archive with default zstd settings. Zstandard rejected the frame: a 1 GiB window exceeds the 128 MiB default. Reopens when: A different release archive or decoder no longer needs the long-window option.KeptCLC-004-llvm-release-zstd-window
N3Preload the facade under NVCC's default (static) runtime linkage. The probe kept reporting runtime version 12040; nothing to interpose. Reopens when: A statically linked target is chosen and a safe rebuild or instrumentation path exists.KeptCLC-005-runtime-static-link-interposition
N4Mask the runtime version and run stock tensor addition on the CUDA 13 wheel. No kernel image for sm_52; version masking cannot supply a missing Maxwell kernel. Reopens when: A Maxwell-targeted kernel or software path for the operator is connected.KeptCLC-006-pytorch-cu130-sm52-kernel-image
N5Stock float32 torch.mm on the official 2.14.0+cu130 wheel. Failed in cuBLAS with CUBLAS_STATUS_ARCH_MISMATCH. Reopens when: A future wheel or compatible cuBLAS runs the same probe on sm_52 without the adapter.KeptCLC-009-stock-mm-cublas-arch-mismatch
N6Stock float32 torch.relu on the official wheel. No kernel image is available for execution on the device. Reopens when: A future wheel ships a ReLU kernel image executable on sm_52.KeptCLC-009-stock-relu-no-kernel-image
E

Registered hypotheses

Registered in the research program before the work, each with the observation that would falsify it. None is graded on this sheet. Site-level predictions about this redesign are registered the same way in records/predictions.jsonl (PRED-SITE-001 to 003).

H1Selected CUDA 13-era PyTorch operations can execute correctly on GM200 without application source changes. Fails if: output mismatch, unreported fallback, or no device execution.Open
H2A reusable Maxwell primitive library reduces per-application adapter work. Fails if: implementation stays framework-specific or correctness fails.Open
H3Modern-facing library adapters can preserve bounded semantics using legacy implementations. Fails if: ABI, stream, precision, or resource contract mismatch.Open
H4Preflight plus runtime evidence predicts support more reliably than toolkit-version gates. Fails if: a false supported status on a mandatory operation.Open
H5Architecture-neutral operation contracts can be implemented on Pascal and beyond. Fails if: the semantic contract needs Maxwell-only assumptions.Open
H6GPU-native paths offer a meaningful benefit over explicit CPU fallback. Fails if: transfer or dispatch cost dominates, or the workload objective fails.Open

Claim status

EstablishedThe source tree includes research logs and local verification records. The site is live at cudacompat.com. Google and Bing read the sitemap on 2026-11-03, and Google reports the homepage indexed.
Receipt onlyThe consent-gated GA4 tag is deployed; one explicitly accepted test visit produced page_view, first_visit, and session_start in Realtime, after which test consent was withdrawn. An event-receipt check, not an audience outcome. Google Search Console verified its property.
Not claimedA successful HTTP fetch or valid sitemap does not prove indexing or ranking. Google’s sitemap report still says “Couldn’t fetch,” and URL Inspection says the homepage is unknown to the index even though the live test says it is available and can be indexed. No indexing, citation, or external distribution outcome is claimed.
