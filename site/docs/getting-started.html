Install CUDA Compatibility for an older NVIDIA GPU

Install the package into the same Python environment as the CUDA-enabled PyTorch wheel. The launcher builds a process-local adapter and starts your script as a child process; it does not install or replace the system driver.

By Zach Shallbetter · Sheet 03 of 10 · Updated 3 November 2026

A

Requirements

  • Linux x86_64.
  • All visible GPUs must report compute capability 5.2.
  • Python 3.10 or newer; the tested environment uses Python 3.10.12.
  • Official PyTorch 2.14.0 CUDA 13.0 wheel in the active environment.
  • LLVM/Clang 23.1.4 with NVPTX support.
  • CUDA 12.4 development headers, a working driver interface, g++, and C++ headers.

The package bundles no NVIDIA toolkit files, runtime libraries, headers, or drivers. The current launcher uses user-installed CUDA 12.4 development headers with the existing driver stack.

B

Four steps

Steps 1 to 3 in one command

curl -fsSL https://cudacompat.com/install.sh | sh

On Linux x86_64, the installer finds the environment that holds the PyTorch CUDA wheel, installs the release into it after checking its SHA-256, and runs cuda-legacy setup. It never uses sudo. Run it as your own user. Inside a container (Docker or Podman) running as root is fine; on another disposable machine where root is the only user, add --allow-root. It refuses sudo, because pip would leave root-owned files in your environment and home. Read install.sh first and compare it with its checksum. Add -s -- --dry-run to see each step, --yes to skip the download question, or --uninstall to remove everything it installed. To upgrade, run the same command again. The steps below do the same by hand.

If cudacompat.com refuses the download (curl prints an HTTP error such as 403 or 429, and nothing runs), fetch the same script from GitHub and check it against its checksum:

curl -fsSLO https://raw.githubusercontent.com/zachshallbetter/cuda-compatibility/main/site/install.sh
curl -fsSL https://raw.githubusercontent.com/zachshallbetter/cuda-compatibility/main/site/install.sh.sha256 | sha256sum -c - && sh install.sh
1

Clone the project and create an environment

git clone https://github.com/zachshallbetter/cuda-compatibility.git
cd cuda-compatibility
python3 -m venv .venv
. .venv/bin/activate

If you already have a dedicated environment containing the target PyTorch wheel, activate it instead. The command must use that same interpreter.

2

Install the package

python -m pip install .

For development, use python -m pip install -e .. In a virtual or Conda environment, the command is installed into that environment’s bin/ directory. Avoid system-wide sudo pip installs.

Distribution status

No CUDA Compatibility package is currently published on PyPI. Install from the GitHub checkout using the steps above; pip install cuda-legacy-compat is not a supported installation command.

3

Set up once

cuda-legacy setup

setup finds the environment that holds PyTorch and the CUDA 12.4 headers, then uses your LLVM 23.1.4 or, after asking, downloads the official llvm-project archive (1.2 GB, SHA-256 checked) and keeps only the compiler (about 370 MB). It saves the result and runs doctor, which lists anything still missing with the exact next step. “Ready” is not a workload certification. --dry-run shows the plan without changing anything; cuda-legacy setup --remove deletes exactly what setup created.

4

Launch a script

cuda-legacy run path/to/app.py --your-option value

cuda-legacy ops lists what runs natively on sm_52 and what is copied to the CPU. If a script stops on an operation with no sm_52 route, the message names it.

Trusted scripts only

The adapter is opt-in and affects only the child Python process. It sets LD_PRELOAD and a Python startup hook, builds temporary bridge and kernel files, and removes those files when the child exits. Use the launcher only with scripts you trust.

C

Homebrew on Linux

Release 0.2.5

Homebrew on Linux can install the command line tool in its own environment instead of steps 1 and 2. The formula installs the tagged 0.2.5 release; add --HEAD to build the current main branch instead.

brew tap zachshallbetter/cuda-compatibility https://github.com/zachshallbetter/cuda-compatibility
brew install cuda-legacy
cuda-legacy setup --python /path/to/your-env/bin/python

Point it at your PyTorch environment

Homebrew installs cuda-legacy with its own Python, which does not contain PyTorch. Pass --python to setup once (it is saved for doctor and run), or set CUDA_COMPAT_PYTHON, with the interpreter of the environment that holds the CUDA-enabled PyTorch wheel. The formula is Linux-only, and its install has not yet been run on the reference host.

For a first run with a known answer, use the public example. It lists the exact commands, the expected output for the stock wheel and for the adapter, and the route each operation takes. Report what you see with the reproduction report form.
