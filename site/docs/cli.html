cuda-legacy command reference

cuda-legacy is the preferred terminal command. Install it into the same Python environment as the CUDA-enabled PyTorch package. The previous cuda-legacy-compat command remains an alias.

A

Commands

CommandPurpose
cuda-legacy --helpList commands and example use.
cuda-legacy help <command>Show command-specific guidance.
cuda-legacy --versionPrint the installed package version.
cuda-legacy inspect [--json]Report visible GPU and compiler inventory as JSON.
cuda-legacy profiles list [--json]List bundled versioned compatibility profiles.
cuda-legacy profiles show PROFILE [--json]Explain a profile’s source and requirements.
cuda-legacy setup [--yes] [--dry-run] [--json] [--python PATH] [--cuda-root PATH] [--llvm-root PATH]Find or download what the launcher needs (LLVM 23.1.4 is SHA-256 checked), save it, and run doctor. Run it once.
cuda-legacy setup --removeDelete exactly what setup created: its LLVM copy and the saved setup. The NVIDIA driver's shared compile cache in ~/.nv is left alone.
cuda-legacy doctor [--llvm-root PATH] [--cuda-root PATH] [--python PATH] [--json]Check prerequisites for the experimental launcher; each missing item names its next step.
cuda-legacy ops [--json]List what the adapter runs natively on sm_52, what it runs through the CPU fallback, and each limit.
cuda-legacy audit PROFILE [--json]Compare available machine facts against a target profile.
cuda-legacy jupyter [--remove]Register (or remove) the Jupyter kernel “Python (cuda-legacy, sm_52)”, which starts through run -m ipykernel_launcher in the saved PyTorch environment; it needs ipykernel there.
cuda-legacy run [options] [-i] (SCRIPT | -m MODULE | -c CODE) [args...]Start a Python script, module or code with the opt-in adapter, as python would; -i alone opens an interactive prompt.
B

Launch options

cuda-legacy run path/to/app.py --application-option value
cuda-legacy run -m mypackage.train      # a module, like python -m
cuda-legacy run -m pytest tests/
cuda-legacy run -c "import torch; print(torch.ones(2).cuda() * 2)"
cuda-legacy run -i                      # an interactive prompt

# override the saved setup for one run
cuda-legacy run --python /path/to/other-env/bin/python -- path/to/app.py

After cuda-legacy setup, run and doctor read the saved setup in ~/.config/cuda-legacy/config.json. A flag wins over an environment variable, which wins over the saved setup. Set CUDA_COMPAT_VERBOSE=1 to see PyTorch's own sm_52 warnings, which the adapter otherwise replaces with one line. You can set CUDA_COMPAT_LLVM_ROOT, CUDA_COMPAT_CUDA_ROOT and CUDA_COMPAT_PYTHON instead of passing the corresponding options. --python selects the interpreter that runs the script and that doctor inspects for PyTorch; it defaults to the interpreter running cuda-legacy, and a missing or non-executable path stops the launch before anything is built. The script and its arguments go after the -- separator.

C

Exit codes

setup0 saved and ready; 1 saved, but doctor lists items to fix; 2 stopped before saving. --dry-run returns the code a real run would.
doctor0 when checked prerequisites are ready; 1 when setup needs attention.
audit0 compatible against recorded profile fields; 1 incompatible; 2 invalid or unreadable profile; 3 required facts unknown.
profiles0 on success; 2 when a profile cannot be read or resolved.
runReturns the child application’s exit code, or 128 + N when signal N ended it, as a shell does; launcher preflight or build errors return 2. Ctrl-C and Jupyter’s interrupt reach the program, which decides what to do; SIGTERM or SIGHUP sent to the launcher is passed on.

“Compatible” and “ready” refer only to fields each command checks. Neither is an operator or workload certification.

D

Common setup errors

  • Missing GPU inventory means nvidia-smi is unavailable; the package does not install drivers.
  • LLVM must be version 23.1.4 and include bin/clang++ with NVPTX support.
  • CUDA headers must include cuda.h and cuda_runtime.h.
  • The current adapter accepts only visible sm_52 devices. Numeric CUDA_VISIBLE_DEVICES selections can restrict a mixed host.
  • “No kernel image” means the wheel lacks an image for that operation and no registered replacement path handled it.

See the support matrix before treating a preflight pass as application support.
