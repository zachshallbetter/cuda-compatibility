The site is a static GitHub Pages site and does not receive server access logs that the project can analyze. A GA4 web stream is configured, and its tag is deployed behind the optional visitor consent choice.

What the site measures

After opt-in, the site sends a page view using the page path, static page title, and referrer origin. It records clicks on a short list of installation, support matrix, GPU catalog, repository, evidence, discovery guide, and external reference links. External link events include only the destination host. Paths omit query strings and fragments. The event code does not collect form values, model inputs, free text, or the full destination URL.

The site uses fonts available on the visitor's device and does not request font files from Google or another font host. This avoids a third-party font request during page load.

Google Analytics may receive browser/device information and an IP address, use the address to infer approximate location, and set first-party cookies to distinguish browsers and sessions. Google says GA4 uses IP addresses at collection time and discards them before data is logged. GA4 also automatically records first_visit, session_start, and user_engagement after consent. Advertising storage, advertising user data, and personalization signals are denied by the site tag. Google Signals, user-provided data collection, ads personalization, and Enhanced Measurement are also off in the Analytics property. This is a data-minimization design, not a legal-compliance certification.

Withdrawing consent blocks this site's named link events, updates Google's consent state to denied, and attempts to remove GA cookies on the current host before reloading. Google may still process a consent update or limited signals. This control cannot delete data already sent to Google; deletion must be requested through the Analytics property.

See Google's documentation on Analytics data handling, automatically collected events, and data retention.

Consent and settings

Visitors see an optional choice before the site loads the Google tag. Accepting stores the choice in this browser and loads the tag; rejecting stores a local preference and does not load it. Visitors can reopen the choice here. If browser storage is unavailable, analytics stays off. The project does not receive or store this consent choice. The configured tag is deployed; requests to Google measurement services begin only after opt-in.

Google's documentation describes the Analytics consent types, the GA4 event model, and data retention settings.

Configure analytics

  1. The project GA4 property and GitHub Pages web stream are configured.
  2. Enhanced Measurement is off so the property does not add automatic scroll, form, or outbound-click events.
  3. Event-level retention is two months. Email redaction is on, and URL redaction covers email, token, access_token, and code parameters. Google Signals, user-provided data collection, and ads personalization are off at the property level; advertising signals are denied by the site tag.
  4. The stream Measurement ID is configured in analytics.js; the consent-gated tag is deployed.
  5. A consented setup test on 2026-11-01 produced page_view, first_visit, and session_start in GA4 Realtime. Test consent was then withdrawn. This one test confirms event receipt only, not audience coverage or outcomes.

After opt-in, the site's named events are page_view, installation_guide_click, support_matrix_click, gpu_catalog_click, project_repository_click, evidence_page_click, discovery_page_click, and external_reference_click. GA4 also automatically records first_visit, session_start, and user_engagement. Keep the property configuration aligned with this scope.

Connect Google Search Console

  1. Publish the site at https://zachshallbetter.github.io/cuda-compatibility/ and confirm it returns public pages over HTTPS.
  2. In Google Search Console, add a URL-prefix property for that exact site address.
  3. Choose HTML-tag verification, copy the verification value, and add the provided google-site-verification meta tag to the homepage head. Keep Google's exact token unchanged.
  4. After verification, submit https://zachshallbetter.github.io/cuda-compatibility/sitemap.xml in the Sitemaps report.
  5. Use URL Inspection for the homepage and key documentation pages. A crawl or indexing request is not a guarantee of indexing, ranking, or timing.

The sitemap and crawler policy are available at sitemap.xml and robots.txt. The URL-prefix property is created and its verification tag is in the homepage source; ownership verification and sitemap submission are pending. No indexing result is claimed.

See Google's guidance on requesting a crawl and submitting a sitemap.

Connect Bing Webmaster Tools

  1. Open Bing Webmaster Tools and choose Import from Google Search Console after the URL-prefix property above is verified. Review the account-access request before granting it.
  2. If you do not want to import, add this exact site prefix in Bing and complete the verification method Bing offers, such as its XML file or meta tag. Keep the supplied verification artifact in the published site; do not invent a token.
  3. Submit https://zachshallbetter.github.io/cuda-compatibility/sitemap.xml in the Sitemaps section.
  4. Check submission status, last-read time, and reported processing errors. Record the date and property prefix with any result; submission alone does not show that pages were indexed.

Bing documents importing verified Search Console properties, site verification methods, and sitemap submission and processing. Bing may periodically revalidate imported ownership through the connected Google account. The Bing URL-prefix property is created; meta-tag verification and sitemap submission are pending.

Measurement is not proof of reach

Analytics can describe measured visits and link clicks. Search Console reports search impressions, clicks, and indexing signals. Neither proves a visitor found the site through a particular recommendation, nor guarantees search visibility. The project will report each metric with its observation window and data source.
