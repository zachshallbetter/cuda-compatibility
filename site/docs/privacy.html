The site is a static GitHub Pages site. It does not receive server access logs that the project can analyze. Optional Google Analytics is disabled until the site owner configures a GA4 web measurement ID; even then, its tag loads only after a visitor accepts analytics.

What the site measures

After opt-in, the site sends a page view using the page path, static page title, and referrer origin. It records clicks on a short list of installation, support matrix, GPU catalog, repository, evidence, and external reference links. External link events include only the destination host. Paths omit query strings and fragments. The event code does not collect form values, model inputs, free text, or the full destination URL.

Google Analytics may receive browser/device information and an IP address, use the address to infer approximate location, and set first-party cookies to distinguish browsers and sessions. Google says GA4 uses IP addresses at collection time and discards them before data is logged. GA4 also automatically records first_visit, session_start, and user_engagement after consent. Advertising storage, advertising user data, personalization signals, and Google Signals are disabled by the site tag. The Analytics property must also have Enhanced Measurement disabled so it does not add events such as scroll or automatic outbound-click tracking. This is a data-minimization design, not a legal-compliance certification.

Withdrawing consent blocks this site's named link events, updates Google's consent state to denied, and attempts to remove GA cookies on the current host before reloading. Google may still process a consent update or limited signals. This control cannot delete data already sent to Google; deletion must be requested through the Analytics property.

See Google's documentation on Analytics data handling, automatically collected events, and data retention.

Consent and settings

When analytics is configured, visitors see an optional choice. Accepting stores the choice in this browser and loads the Google tag. Rejecting stores a local preference and does not load the tag. Visitors can reopen the choice here. If browser storage is unavailable, analytics stays off. The project does not receive or store this consent choice.

The current source does not include a GA4 measurement ID, so analytics and the consent prompt are inactive until the site owner adds one to analytics.js. No visitor analytics are currently being collected by this project site.

Google's documentation describes the Analytics consent types, the GA4 event model, and data retention settings.

Configure analytics

  1. Create a GA4 property and web data stream for the published project site.
  2. Disable Enhanced Measurement in the stream so the property adds no scroll, form, or automatic outbound-link events.
  3. Disable Google Signals and advertising features, and set event-level data retention to two months.
  4. Copy the web stream Measurement ID (format G-…) into measurementId in analytics.js.
  5. After publication, use GA4 Realtime/DebugView to confirm the expected events, then remove test/debug traffic from reporting.

After opt-in, the site's named events are page_view, installation_guide_click, support_matrix_click, gpu_catalog_click, project_repository_click, evidence_page_click, and external_reference_click. GA4 also automatically records first_visit, session_start, and user_engagement. Keep the property configuration aligned with this scope.

Connect Google Search Console

  1. Publish the site at https://zachshallbetter.github.io/cuda-compatibility/ and confirm it returns public pages over HTTPS.
  2. In Google Search Console, add a URL-prefix property for that exact site address.
  3. Choose HTML-tag verification, copy the verification value, and add the provided google-site-verification meta tag to the homepage head. Keep Google's exact token unchanged.
  4. After verification, submit https://zachshallbetter.github.io/cuda-compatibility/sitemap.xml in the Sitemaps report.
  5. Use URL Inspection for the homepage and key documentation pages. A crawl or indexing request is not a guarantee of indexing, ranking, or timing.

The sitemap and crawler policy are available at sitemap.xml and robots.txt. Search Console setup has not been completed, and no live indexing result is claimed.

See Google's guidance on requesting a crawl and submitting a sitemap.

Measurement is not proof of reach

Analytics can describe measured visits and link clicks. Search Console reports search impressions, clicks, and indexing signals. Neither proves a visitor found the site through a particular recommendation, nor guarantees search visibility. The project will report each metric with its observation window and data source.
