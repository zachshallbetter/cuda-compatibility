Native Maxwell operator kernels

Selected PyTorch operations use LLVM-generated PTX compiled for the real sm_52 device and launched through the CUDA Driver API: add, arange, embedding, layer norm, matmul, and ReLU. Float16 add, strided matmul, and seven SGD steps of a 2×2 linear → ReLU → sum model are verified on GPUs 1 and 2.

CPU fallback and a training slice

Selected CPU fallbacks preserve first-order gradients for a tested linear → ReLU → sum path. A small SGD update runs through a native float32 in-place add kernel. Each fallback is limited to 64 MiB of inputs and 64 MiB of outputs.

Operator support

Sheet 01 / 10

Runs on the GPU

Native sm_52 kernel
8 registered cases, 6 operation families
  • Tensor additionContiguous float32 (up to 1,048,576 values) and int32 tensors (up to 2,147,483,647); same shape and device, alpha=1.
  • Float16 additionSame-shape contiguous float16 tensors, alpha=1, up to 1,048,576 values; edge values checked exactly.
  • Float32 in-place additionSame-shape contiguous float32 tensors, up to 1,048,576 values; supports the scaled updates used by the tested SGD step.
  • Range creationCUDA int64 arange, up to 1,048,576 values.
  • EmbeddingInference with float32 weights and int64 indices; 1D or 2D indices, up to 1,048,576 output values.
  • Layer normalizationInference on contiguous float32 input over the last dimension with float32 weight and bias; up to 1,048,576 values.
  • Matrix multiplication2D float32 matrices with nonnegative strides; each dimension up to 256, at most 16,777,216 multiply-accumulate steps.
  • ReLUContiguous float32 tensors, up to 1,048,576 values.

Native forward kernels are not differentiable. Grad-enabled calls on these operations use differentiable CPU transfers instead.

Runs through CPU fallback

Bounded autograd
Operation / CPU implementation
  • Linear algebralinear, bmm
  • Attention and activationssoftmax, scaled_dot_product_attention, GELU
  • Arithmeticadd, multiply, divide
  • Reductionssum, clamp_min
  • Layoutconcatenate, contiguous

These use PyTorch’s CPU implementation with differentiable host and device transfers on selected first-order gradient paths. The dispatcher can also retry eligible out-of-place operations after recognized missing-image, architecture-mismatch, or cuDNN no-engine errors.

Fallback requires one CUDA device. Training evidence is limited to linear → ReLU → sum with float32 SGD (foreach=False); other autograd and optimizer paths are unverified.

Scope

The launcher is a workload adapter for a narrow PyTorch subset, not a universal CUDA 13 runtime. It requires Linux x86_64 and homogeneous visible sm_52 GPUs. It interposes one runtime-version query and does not replace the CUDA 13 API surface or implement general cuDNN, cuBLAS, NCCL, or Triton compatibility. Other devices, operations, optimizers, dtypes, layouts, and library paths need their own implementations and evidence.

To check it yourself, run the public example: one small network pinned to a release, machine and expected output, showing which route each operation takes and two cases that fail. Then send a reproduction report, pass or fail.

Why this project exists

NVIDIA’s CUDA 13 release notes say offline compilation and library support for Maxwell, Pascal, and Volta were removed from the toolkit. This project measures how much useful application behavior can be recovered with a compiler path, adapters, and faithful fallbacks, without hiding the real device.

Try the prototype

Sheet 01 / 10

Install into the same Python environment that already holds the official CUDA 13 PyTorch wheel. The package installs no NVIDIA components and changes nothing system-wide.

The command lands in that environment’s bin/. For a user-site install, find the scripts path with python3 -m site --user-base and add /bin to PATH. The Python used for that install must already contain PyTorch. Python Packaging User Guide

Trusted scripts only

The launcher uses LD_PRELOAD and Python startup customization. Start with the probes in the repository and compare every result with a CPU reference.

1

Install into the PyTorch environment

# from the project checkout, in the target PyTorch environment
python -m pip install .
2

Check the host and target

cuda-legacy inspect
cuda-legacy doctor
cuda-legacy profiles show pytorch-2.14-cu130
3

Launch one trusted script

cuda-legacy run \
  --llvm-root /path/to/LLVM-23.1.4 \
  --cuda-root /usr/local/cuda-12.4 \
  -- app.py

Other versions and cards may work but have not been validated.
